Desktop nedir, terminalden farkı ne?

Aynı motor, farklı kabin. Terminaldeki her şey (kurallar, skill, agent, hook, git) burada da var — ama komut yazmak yerine pencere + buton ile.

Önemli: .claude/ klasörü, kurallar, journal, skill, agent, hook — hepsi birebir aynı. Bu rehber boyunca "söyle/onayla" derken paneldeki sohbeti kastediyoruz.
Vurgu: Penceredeki otomatik kolaylıklar (açılış özeti, plan-onay, otomatik diff/commit, güvenlik bloğu) Claude'un hazır sihri değil — senin .claude/ altına yazdığın/yazdırdığın skill, agent ve hook'lar sayesinde. Masaüstü sadece kabin; akıl o dosyalarda.

L0

Acemi — "Uygulamayı kullanabiliyorum"

Hedef: Pencereyi açıp iş yaptırmak. Kod/terminal bilmeden.

Kazanımlar

  • Uygulamayı aç → proje klasörünü seç
  • Sohbet paneline günaydın yaz, özeti oku
  • Hedefi net söyle → plan kutusunu oku → İzin Ver
  • Görsel diff'i incele (yeşil=eklendi, kırmızı=silindi)
  • "bunu commit'le" ile kaydet

Araçlar

günaydıniyi gecelerİzin Ver butonudiff paneli

Oluşturma: Henüz yok. Skill/hook kurulu geldi; sen tetikliyorsun.
Desktop avantajı: Onay butonları sayesinde "yanlışlıkla onay" zorlaşır — her değişikliği görsel görüp tıklarsın.
Geçiş → L1: Bir haftalık işi yardımsız bitirdiysen Junior'sın.
L1

Junior — "Araçları kullanıyorum"

Hedef: Hazır komut/skill/kuralları bilinçli kullanmak.

Kazanımlar

  • / menüsünden komut: /code-check, /verify, /security-check
  • /compact (devam) vs /clear (yeni iş) farkı
  • Kuralları okur (dosya ağacından .claude/rules/); TODO/journal takip
  • Commit disiplini: 1 commit = 1 konu; 15 dosya uyarısını dinle

Skill/agent/hook oluşturma — bu seviyede

Kural ürettirirsin (sohbette):

# Panele yaz:
bunu kalıcı kurala yaz: tüm tarihler gg.aa.yyyy formatında olsun
# Claude .claude/rules/ altına işler, onay kutusu çıkar → İzin Ver
Junior refleksi: Aynı şeyi 2. kez söylüyorsan "kurala yaz" de.
Geçiş → L2: "Buna özel bir skill olsa" demeye başladıysan Senior'sın.
L2

Senior — "Araç üretiyorum"

Hedef: Proje-özel skill / agent / hook oluşturmak.

Kazanımlar

  • Skill/agent/hook oluşturur (frontmatter, tetik, kısıt)
  • Model katmanı: haiku (mekanik) / sonnet (analiz) / opus (yüksek-risk)
  • Salt-okuma vs yazma ayrımı (denetçi agent yazamaz)
  • Tier 3 işte plan; agent çağırır (code-review, security)

En pratik yol: Claude'a yazdır

# Panele yaz:
Bana "rapor-yazici" skill'i oluştur. Excel rapor üretirken
şu kolonları zorunlu tutsun, "rapor çıkar" denince tetiklensin.
salt-okuma olsun. # Claude SKILL.md yazar → onayla

Frontmatter — bilmen yeten kadar

---
name: rapor-yazici
description: Excel rapor standardı. "rapor çıkar" denince tetiklenir.
allowed-tools: Read, Grep, Glob   # yazma yok = güvenli
model: inherit
---
description = tetikleyici sözleşme. Gerçek cümleleri buraya göm; Claude ne zaman çağıracağını oradan bilir.
Hook (otomatik koruma): "commit öncesi şifre taraması yapan bir hook ekle" de — Claude script + settings.json kaydını yapar.
Geçiş → L3: Başka devler senin kurallarını soruyorsa Leader'sın.
L3

Leader — "Ekip standardı kuruyorum"

Hedef: Template'i ekibe yaymak, kararları sistematik kılmak.

Kazanımlar

  • Yeni projeye template kurar (bootstrap); --update ile yayar
  • Evrensel / stack / proje kural ayrımını yönetir
  • Mimari karar → ADR; kararsızlıkta council this
  • Agent + hook ekosistemi (faz-kapanış kapısı: build→review→security)
  • Onboarding: yeni dev'e acemi rehberi → bu rehber
Desktop notu: bootstrap script'i terminalde/uygulamanın komut panelinde çalışır. Leader seviyesinde komut satırına biraz değmen gerekir — Claude'a "şu projeye template kur" desen de yapar.

Governance

Stale skill/kural = aktif zarar. "Son 2 ayda tetiklendi mi, hâlâ doğru mu?" Hayır → emekli et.

Geçiş → L4: Çok-ajanlı orkestrasyon / MCP ihtiyacı doğduysa Plus'tasın.
L4

Plus — "Sistemi otomatikleştiriyorum"

Hedef: Tek bağlama sığmayan işleri orkestre etmek; kendi tool'unu bağlamak.

Kazanımlar

  • Workflow orkestrasyon: çok agent fan-out + adversarial verify
  • MCP server (kendi DB/API'ni Claude'a tool olarak bağla)
  • Çok-hook'lu pipeline (format + lint + test + bildirim)
  • Zamanlanmış/loop görevler
  • Meta: telemetri, ölçüm, sistemin kendini iyileştirmesi
Plus zihniyeti: Tek tek işleri değil, iş üreten sistemleri tasarlarsın. Token bütçesi + doğrulama birinci sınıf girdi.
Tuzak: Güçlü ≠ gerekli. Workflow/MCP pahalı; ihtiyaç kanıtlanmadan kurma.
